Data Breach in a Research Data Commons

A research community stores 120 sensitive records on 36 nodes. An adversary starts compromising nodes. The testbed compares two ways of holding data: whole records in one place (the object-centric paradigm) and records dissolved into shares across the field (the LDF paradigm), and measures how much data leaks, how fast defence reacts, and what it costs.

Cost = exposed records × record value + response events × response cost × 0.5. Response events are quarantines plus share refreshes, and they are charged to both designs. Units are relative and the weights are editable assumptions, not currency.

Principle 1: threshold sharing

record → n = 5 shares, any k = 3 reconstruct

Cryptography (Shamir, 1979): fewer than k shares reveal nothing about the record. The fabric stores each record this way across five random nodes, so an attacker must hold three of a record's five nodes at once. The object-centric store needs only one node. LDF's own encoding is field and topological-code inspired, and threshold sharing is the established proxy used here.

Principle 2: peer monitoring

P(detect) = 1 − (1 − d)m

Immune-system logic. In the fabric, each compromised node is watched by m honest neighbours, each noticing anomalies with probability d per tick. In the object-centric design only the controller monitors, so if the controller itself falls, nobody notices. This is a stated modelling assumption, and you can change d.

Principle 3: proactive refresh

detect → quarantine 20 ticks → refresh shares

Proactive secret sharing (Herzberg et al., 1995) re-randomizes shares so stolen ones become useless, like cell turnover limiting a pathogen. A record that was already reconstructed stays exposed. Refresh only stops further accumulation.

Method, assumptions, and limitations

  • Setup: 36 nodes, 120 records, seeded layout and seeded random draws, so a run repeats exactly for the same settings. The attacker compromises one node per interval (set by the attack-rate slider).
  • Informed attacker: always targets the honest node with the most data holdings. Random attacker: draws the same random target for both designs.
  • Analytic check: for c randomly compromised nodes, the expected fraction of exposed records is the hypergeometric tail P(X ≥ 3), X ~ Hypergeometric(36, c, 5). The fabric panel shows it next to the simulated value.
  • What the result means: object-centric exposure is all-or-nothing at one node. Fabric exposure depends on a race between attack rate and detection. Push the attack rate up and the detection down and the fabric breaks too. The claim is a higher breach threshold and slower, graceful degradation, not invulnerability.
  • Limits: a software simulation; the object-centric store is a stylised single store (real systems add replication and encryption at rest); detection probabilities are assumptions; one run per setting with no statistical replicates; no network or hardware layer. Planned work: Monte Carlo over seeds, stronger baselines (encrypted replicated stores), an adaptive attacker, and an edge testbed.
